# Contributing

Спасибо за интерес к проекту.

## Как сообщить об ошибке

Создайте issue и укажите:

- версию ОС и компилятора;
- команду, которой запускался архиватор;
- минимальный входной файл или способ его получить;
- ожидаемый и фактический результат.

Если ошибка связана с поврежденным архивом, приложите файл архива или
короткий скрипт, который его создает.

## Как подготовить изменение

1. Создайте отдельную ветку от `main`.
2. Внесите изменение небольшими осмысленными коммитами.
3. Проверьте форматирование и тесты локально.
4. Откройте pull request с описанием проблемы, решения и выполненных проверок.

## Локальные проверки

```bash
cmake -S . -B build
cmake --build build
ctest --test-dir build --output-on-failure
bash tests/test.sh
clang-format --dry-run --Werror $(git ls-files '*.c' '*.h')
```

Для проверки перед коммитом можно установить `pre-commit`:

```bash
python3 -m pip install pre-commit
pre-commit install
pre-commit run --all-files
```

## Стиль кода

- C11 без compiler-specific расширений.
- Имена функций и переменных в `snake_case`.
- Публичные функции описываются в заголовочных файлах.
- Форматирование задается `.clang-format`.
